Add cookie-mode sessions. `defineCredentialAuthModule({ sessions: { transport: "bearer" | "cookie" | "both", cookie: { name, path, domain, sameSite, secure, csrf: { cookieName, header } }, environment } })` lets sign-in, TOTP verify and recovery consume install an `httpOnly`, `Secure`, `SameSite=Lax` (or `Strict`) cookie carrying the opaque session token through an optional `transport` body field; the body then carries `session.transport: "cookie"` without a token. Sign-out, revoking the current session and revoke-all clear the cookie; TOTP confirmation rotates a cookie session and returns the replacement as `session`. `secure: false` is refused unless `sessions.environment` is `"development"`; cookie transports require `clients`. `credentialAuthentication({ sessions })` / `credentialSessionCredentials({ sessions })` read the cookie when no bearer header is present; a stale cookie session resolves anonymously on public operations and is refused on authenticated ones. New `credentialSessionCsrfPolicy({ auth, trustedOrigins })` for the adapter's `"*"` pre-validation key: safe methods exempt, Origin/Referer validation (trusted list plus the request's own origin), the double-submit `ship_csrf` cookie echoed in `x-csrf-token`, login-CSRF origin checks on session-issuing operations, and the CSRF cookie issued by the policy. Also exported: `resolveSessionPolicy`, `serializeSessionCookie`, `clearSessionCookie`, `serializeCsrfCookie`, `readCookie`, `generateCsrfToken`, the cookie defaults, and the session token view now carries `transport` with an optional `token`. `RequestClient` gains `sessionTransport`.
