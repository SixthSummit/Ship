# {{PROJECT_NAME}}

A ShipAPI v4 application. Generated by `npx ship-api create my-app`.

## Stack

- **HTTP**: Hono (`@hono/node-server`)
- **Validation**: Zod 4 + `@hono/zod-validator`
- **ORM**: Drizzle (Postgres)
- **Auth**: Pluggable `AuthProvider` (Firebase by default)
- **Jobs**: BullMQ
- **Observability**: pino + OpenTelemetry (auto-instrumented)
- **Typed client**: `hc<ShipApiClient>()` — schema → types → client, no codegen

## Quick start

```sh
# 1. Install deps
npm install

# 2. Copy + populate env
cp .env.example .env
# Generate a 32-byte OAUTH_STATE_SECRET (any of these works):
#   openssl rand -hex 32
#   node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"

# 3. Bring up dependencies + start dev server in one shot
ship-api dev
# (Brings up Docker Compose for Postgres / Redis / OTel collector,
# then `tsx watch src/index.ts`, then waits for /livez to go green
# before printing the URL.)

# 4. Run migrations against the dev db
npm run db:generate -- --name initial
npm run db:migrate
```

## Common workflows

```sh
ship-api g module billing               # scaffold a CRUD module
ship-api g resource posts \
  --fields "title:string,body:text,published:boolean,publishedAt:timestamp?"
                                        # CRUD module from a field spec
ship-api g middleware rate-limit-by-key # add a Hono middleware
ship-api g job send-invoice-email -m billing  # add a BullMQ job stub

ship-api g doctor                       # project health check
ship-api migrate-orm <path>             # codemod TypeORM entities → Drizzle
```

## Conventions

The framework's load-bearing conventions are documented in:

- **AGENTS.md** at the repo root — the entry-point doc for AI coding agents.
- The Claude Code plugin's skills (auto-loaded when this file is in the workspace).
- The framework's `.cursor/rules/*.mdc` (synced into the plugin's SKILL.md files).

The shortest version:

- Routes: each module exposes `buildXxxApp(deps)` returning its own sub-app (on `createModuleApp("xxx")`); mount via `root.route("/", buildXxxApp(deps))` (preserves RPC types end-to-end via `hc<ShipApiClient>()`, and keeps `tsc` bounded as modules grow). `defineXxxRoutes(app, deps)` is a kept escape hatch — threading one shared app through several modules detonates `tsc`.
- Auth: `requireAuth({ provider })` runs the AuthProvider chain; `requirePermission(slug)` enforces against the resolved user.
- Validation: `validate("json" | "query" | "param", schema)` wraps `zValidator`; handlers read parsed input via `c.req.valid("json" | …)`. Never `c.req.json()` directly.
- Errors: throw from the AppError taxonomy (`NotFoundError`, `BadRequestError`, etc.); `registerErrorHandlers(app)` shapes the JSON response.
- Services: extend `DrizzleEntityService<typeof table>` for inherited CRUD + soft-delete + audit auto-stamping.
- Migrations: `drizzle-kit generate` from schema source. Never hand-edit `src/db/migrations/*.sql`.
- Logging: `import { logger } from "@sixthsummit/ship-api/observability/logger"`. Never `console.log`.
- Env: route application config through the validated `env` object. Only the
  early `instrumentation.ts` boundary reads standard OTel variables directly.
- Permissions: per-action slug naming (`module:resource:action`), exported as constants.
