# @sixthsummit/ship-auth-credentials

## 0.2.0

### Minor Changes

- 8b5633c: Add `auth.change-password` (`POST /auth/password/change`, authenticated): `{ currentPassword, newPassword, signOutOtherSessions? }` re-enters the password under the lockout policy, checks the new one against the password policy, rotates the current session whatever its transport (the response carries the replacement as `session`: a new bearer token, or a new cookie installed through `Set-Cookie`; the old token is revoked as `rotated`) and revokes every other session as `password-changed` unless `signOutOtherSessions` is `false`; audited as `password.changed`. The cookie-reading credential adapter now requires the CSRF guard at construction: `credentialSessionCredentials({ sessions })` / `credentialAuthentication({ sessions })` with a cookie transport declare a `ship-hono` policy requirement for `credentialSessionCsrfPolicy()` under the `"*"` key (alone or in a list), and `createHonoAdapter` fails with `SHIP_HONO_OPTIONS_INVALID` without it. New exports `CREDENTIAL_CSRF_POLICY_ID` and `credentialSessionCsrfRequirement(sessions)` for consumers composing their own credential adapter.
- 4639db8: Add cookie-mode sessions. `defineCredentialAuthModule({ sessions: { transport: "bearer" | "cookie" | "both", cookie: { name, path, domain, sameSite, secure, csrf: { cookieName, header } }, environment } })` lets sign-in, TOTP verify and recovery consume install an `httpOnly`, `Secure`, `SameSite=Lax` (or `Strict`) cookie carrying the opaque session token through an optional `transport` body field; the body then carries `session.transport: "cookie"` without a token. Sign-out, revoking the current session and revoke-all clear the cookie; TOTP confirmation rotates a cookie session and returns the replacement as `session`. `secure: false` is refused unless `sessions.environment` is `"development"`; cookie transports require `clients`. `credentialAuthentication({ sessions })` / `credentialSessionCredentials({ sessions })` read the cookie when no bearer header is present; a stale cookie session resolves anonymously on public operations and is refused on authenticated ones. New `credentialSessionCsrfPolicy({ auth, trustedOrigins })` for the adapter's `"*"` pre-validation key: safe methods exempt, Origin/Referer validation (trusted list plus the request's own origin), the double-submit `ship_csrf` cookie echoed in `x-csrf-token`, login-CSRF origin checks on session-issuing operations, and the CSRF cookie issued by the policy. Also exported: `resolveSessionPolicy`, `serializeSessionCookie`, `clearSessionCookie`, `serializeCsrfCookie`, `readCookie`, `generateCsrfToken`, the cookie defaults, and the session token view now carries `transport` with an optional `token`. `RequestClient` gains `sessionTransport`.
- 04a2a8e: Change two defaults in `@sixthsummit/ship-auth-credentials`. Passwords hash with argon2id from `node:crypto` (`argon2idPasswordHasher`, 64 MiB, t=3, p=1, standard PHC string); the hasher also verifies and flags `$scrypt$` hashes for rehash on sign-in, and `scryptPasswordHasher` remains available. `onExistingEmail` defaults to `"conceal"`: `register` answers 201 for an address that already has an account and mails the owner a verification link (unverified) or the new `existingAccount` notice (verified) linking to the new `links.signIn`, which is required in this mode. Set `onExistingEmail: "reject"` to keep the 409.
- a6123ad: `auth.change-password` mails the account's address the new `passwordChanged` message after every successful change, whoever made it. The notice carries a short-lived reset link (`policies.tokens.passwordChangedResetTtlMs`, 10 minutes by default) so an owner who did not make the change can retake the account; earlier reset links are revoked by the change. The response gains `notified`; a notice the mail queue refuses is audited as `password.changed-notice` and does not fail the change. `defineCredentialAuthMailer()` therefore declares five messages; consumers with custom `templates` may add `passwordChanged`.
- d86f629: A stale session cookie (unknown, revoked, expired, idle, cut off or malformed) is now cleared and audited. `credentialActorResolver({ sessions })` / `credentialAuthentication({ sessions })` attach a clearing `Set-Cookie` to the resolution so the browser stops presenting the dead cookie whether the operation resolved anonymously or was refused, and record one `session.stale-cookie` audit row with the reason, the operation id and the known account and session when there is one. `StaleSessionReason` is exported.
- 96dc12d: Initial release of first-party credential authentication (SAPI-755). `defineCredentialAuthModule({ store, mailer, mail, links, secrets, policies })` composes register, email verification, sign-in with lockout, sessions (list, revoke, revoke-all with the account cutoff), password reset, change-email, TOTP enrolment, challenge and recovery codes as declared operations under `/auth/*` with an audit row for every outcome; `credentialAuthentication()` is a kernel actor provider beside the Firebase resolver; `credentialAuthRateLimitPolicies()` rides the Hono pre-validation hook; `shipAuthTables()` and `createDrizzleCredentialStore()` (subpath `./drizzle`) own the seven tables through the gated migration path; `credentialAuthConsoleExtension()` (subpath `./console`) adds the auth-audit panel to the ops console; `credentialStoreConformance` (subpath `./conformance`) proves any store. Passwords are scrypt-hashed, TOTP follows RFC 6238 with a replay guard, tokens are stored as SHA-256 only and MFA secrets are AES-256-GCM sealed under a key ring.
