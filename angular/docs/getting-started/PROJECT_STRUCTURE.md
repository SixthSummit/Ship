# Generated project structure

```text
project/
├── src/
│   ├── api.ts                         app-specific typed operation-client DI boundary
│   ├── app/
│   │   ├── app.config.ts              providers and request-scoped client registration
│   │   ├── app.routes.ts              guarded or explicitly public routes
│   │   ├── modules/<feature>/         app-owned generated features
│   │   └── pages/                     app shell pages
│   ├── environments/                  browser/server-safe API origin and Firebase config
│   ├── mocks/                         deterministic MSW fixtures
│   ├── server.ts                      Angular SSR server
│   └── test-setup.ts                  Vitest/Angular test bootstrap
├── e2e/                               Playwright browser checks
├── .claude/ and .cursor/              application-facing agent guidance
├── .github/workflows/                 CI, tests, security, deployment
├── Dockerfile                         SSR production image
├── angular.json
├── package.json
└── pnpm-lock.yaml                     generated by the first install and committed
```

`src/app/modules` is owned and versioned by the application. There is no hidden framework
source-copy catalog. Every feature should be included in the app's compiler, lint, tests,
dependency analysis, and browser checks.

`src/api.ts` imports only a browser-safe contract type and the `/operations` entrypoint.
It must not import the ShipAPI runtime, a Hono app, handlers, database schema, or server
auth/observability packages.

SSR request credentials are sanitized by the client provider. Forward only explicitly
approved cookies and headers and never retain a request context globally.
